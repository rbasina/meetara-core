# 📦 Data Management Guide

Guide for managing large data directories (`vectorstore/`, `downloads/`, `images/`, `data/`) in Meetara Core.

> ⚠️ **Important**: `vectorstore/` contains your processed knowledge base - **backup regularly**!

---

## 🚫 **These Directories Are NOT in Git**

The following directories are **excluded from git** (via `.gitignore`) because they contain large binary files:

- **`vectorstore/`** - ChromaDB vector stores (**1.52 GB / 1,556.8 MB**, 66 files) ⚠️ **CRITICAL - Backup regularly!**
- **`downloads/`** - Downloaded PDFs and documents (~4.71 GB)
- **`images/`** - Extracted images from documents (~3.61 GB)
- **`data/`** - Uploaded and exported data
- **`logs/`** - Application logs

**Why?**
- These directories can be **very large** (GBs)
- Git is not designed for large binary files
- They can be regenerated or downloaded as needed
- Reduces repository size and clone time

---

## 🗜️ Quick Compression & Sharing Guide

**Need to share vectorstore quickly?** Use these scripts:

**Windows PowerShell:**
```powershell
# Compress
.\scripts\compress_vectorstore.ps1

# Extract
.\scripts\extract_vectorstore.ps1 -ZipFile "vectorstore_backup_20251122.zip"
```

**Manual Compression:**
```powershell
# Windows
Compress-Archive -Path vectorstore -DestinationPath "vectorstore_backup.zip" -CompressionLevel Optimal

# Linux/Mac
tar -czf vectorstore_backup.tar.gz vectorstore/
```

**Expected Results:**
- **Original**: 1.52 GB (1,556.8 MB)
- **Compressed**: ~1.1-1.4 GB (10-30% reduction)
- **Compression time**: 2-5 minutes
- **Extraction time**: 1-3 minutes

- `bipolar_disorder`: 1.35 MB (5 files)
- `stress_management`: 0.77 MB (5 files)
- `education`: 0.16 MB (1 file)
- `space_technology`: 0.16 MB (1 file)

**Structure**:
```
vectorstore/
├── general_health/
│   ├── chroma.sqlite3
│   ├── chroma.sqlite3-shm
│   ├── chroma.sqlite3-wal
│   └── [embedding files]
├── academic_tutoring/
│   └── [same structure]
└── [other domains]/
```

**Management**:
- **⚠️ CRITICAL**: Contains your processed knowledge base
- **Auto-Generated**: Created when documents are uploaded
- **Per-Domain**: Separate ChromaDB collection per domain
- **Compressed**: Uses Snappy compression (75-85% reduction)
- **Backup Recommended**: This is your processed data - backup regularly!
- **Regeneration**: Can be regenerated by re-uploading documents

**Why NOT in Git?**
- **Large Size**: 1.52 GB+ (grows with more documents)
- **Binary Format**: ChromaDB uses SQLite + binary files
- **Frequently Changing**: Updates with every document upload
- **Can Be Regenerated**: Re-upload documents to recreate

**Backup Strategy**:
- **Regular Backups**: Copy entire `vectorstore/` directory
- **Before Major Changes**: Backup before bulk operations
- **Version Control**: Use external backup, not git
- **Restore**: Copy backup back to `vectorstore/` directory

## 💾 Storage Recommendations

### Option 1: Local Storage (Recommended for Development)

**Keep everything locally** on your development machine:

```
✅ Pros:
- Fast access
- No internet required
- Full control

❌ Cons:
- Takes up disk space
- Not shared across machines
```

**Best for**: Development, testing, single-user scenarios

### Option 2: External Storage

**Store on external drive or network storage**:

```
✅ Pros:
- Frees up main disk
- Can be shared
- Easy backup

❌ Cons:
- Requires external drive
- Slower access
```

**Best for**: Large datasets, shared development

### Option 3: Cloud Storage (Optional)

**Use cloud storage** (Google Drive, OneDrive, Dropbox, etc.):

```
✅ Pros:
- Accessible from anywhere
- Automatic backup
- Can be shared

❌ Cons:
- Requires internet
- May have sync delays
- Storage limits
```

**Best for**: Backup, sharing with team

### Option 4: Git LFS (Not Recommended)

**Git Large File Storage** - Not recommended for this use case:

```
❌ Cons:
- Adds complexity
- Requires Git LFS setup
- Still increases repo size
- Not ideal for frequently changing files
```

## 🧹 Cleanup Strategies

### Vectorstore Cleanup

**Clear a domain (remove all documents):**
```bash
# Interactive mode (asks for confirmation)
python scripts/clear_domain.py clear general_health

# Auto-confirm (skip prompt)
python scripts/clear_domain.py clear general_health --confirm

# Also delete database files (complete cleanup)
python scripts/clear_domain.py clear general_health --delete-db

# Delete entire domain directory
python scripts/clear_domain.py delete general_health
```

**VACUUM database (reclaim space, reduce bloat):**
```bash
# Optimize a domain's database
python scripts/vacuum_domain.py general_health
```

**Check vectorstore size and statistics:**
```bash
# Check single domain
python scripts/check_size.py general_health

# Check all domains
python scripts/check_size.py all
```

### Cleanup Old Downloads

**Windows PowerShell:**
```powershell
# Remove PDFs older than 30 days (after upload)
Get-ChildItem downloads\ -Recurse -Filter "*.pdf" | Where-Object {$_.LastWriteTime -lt (Get-Date).AddDays(-30)} | Remove-Item
```

**Linux/Mac:**
```bash
# Remove PDFs older than 30 days (after upload)
find downloads/ -name "*.pdf" -mtime +30 -delete
```

### Cleanup Old Images

**Windows PowerShell:**
```powershell
# Remove images older than 90 days
Get-ChildItem images\ -Recurse -Filter "*.png" | Where-Object {$_.LastWriteTime -lt (Get-Date).AddDays(-90)} | Remove-Item
```

**Linux/Mac:**
```bash
# Remove images older than 90 days
find images/ -name "*.png" -mtime +90 -delete
```

### Cleanup Temporary Data

**Windows PowerShell:**
```powershell
# Clean temporary uploads
Remove-Item data\uploads\* -Recurse -Force
```

**Linux/Mac:**
```bash
# Clean temporary uploads
rm -rf data/uploads/*
```

## 🔐 Backup Recommendations

### What to Backup

**⚠️ CRITICAL - Backup Regularly**:
- **`vectorstore/`** - Your processed knowledge base (~1.52 GB)

  - **Cannot be easily regenerated** without re-uploading all documents

  - **Backup frequency**: Weekly or before major changes

**Important** (backup periodically):
- Configuration files (`config/*.yaml`) - Domain and keyword configs
- `.env` file (securely) - Environment variables

**Optional** (backup if needed):
- `downloads/` - Source documents (can be re-downloaded)

### Backup Methods

1. **External Drive**: Simple, fast, offline
2. **Cloud Storage**: Automatic, accessible
3. **Version Control**: For config files only (not data)
4. **Database Export**: For vectorstore (if needed)

## ❓ FAQ

### Q: Can I share these directories with my team?

**A**: Yes, but not via git. Use:
- Network shared drive
- Cloud storage (Google Drive, OneDrive)
- External drive
- Each team member processes locally

### Q: What if I accidentally commit these directories?

**A**: Remove them from git history:
```bash
git rm -r --cached downloads/ images/ data/
git commit -m "Remove large data directories from git"
```

### Q: Can I regenerate images from PDFs?

**A**: Yes! Images are extracted during document upload. Re-upload the PDF to regenerate images.

### Q: How do I backup my vectorstore?

**A**: 

**Option 1: Uncompressed Backup (Faster, Larger)**
```powershell
# Windows PowerShell
Copy-Item -Path vectorstore -Destination "backup/vectorstore_$(Get-Date -Format 'yyyyMMdd')" -Recurse

# Linux/Mac
cp -r vectorstore backup/vectorstore_$(date +%Y%m%d)
```

**Option 2: Compressed Backup (Slower, Smaller) - Recommended for Sharing**
```powershell
# Windows PowerShell
$date = Get-Date -Format 'yyyyMMdd'
Compress-Archive -Path vectorstore -DestinationPath "backup/vectorstore_$date.zip" -CompressionLevel Optimal

# Linux/Mac
date=$(date +%Y%m%d)
tar -czf backup/vectorstore_${date}.tar.gz vectorstore/
```

**Important**: 
- Backup the **entire** `vectorstore/` directory
- Include all domain subdirectories
- **Compress for sharing** - Reduces size by 10-30%
- Test restore process periodically
- Keep multiple backup versions

### Q: Can I regenerate vectorstore from documents?

**A**: Yes, but you need the original PDFs. Re-upload all documents via API or batch uploader script. This will recreate the vectorstore, but:
- Takes time (processing all documents)
- May have different embeddings (if model updated)
- Loses any manual metadata edits

**Recommendation**: Always backup vectorstore before major operations.

### Q: How do I restore vectorstore from backup?

**A**:
```bash
# Stop the application first!
# Then restore:
# Windows PowerShell
Remove-Item vectorstore -Recurse -Force
Copy-Item -Path "backup/vectorstore_20251122" -Destination vectorstore -Recurse

# Linux/Mac
rm -rf vectorstore
cp -r backup/vectorstore_20251122 vectorstore
```

### Q: Can I share vectorstore with team members?

**A**: Yes! **Compress and share** via external storage:

**Step 1: Compress vectorstore**

**Windows PowerShell:**
```powershell
# Compress vectorstore to zip file
$date = Get-Date -Format 'yyyyMMdd_HHmmss'
Compress-Archive -Path vectorstore -DestinationPath "vectorstore_backup_$date.zip" -CompressionLevel Optimal

# Check compressed size
$zipSize = (Get-Item "vectorstore_backup_$date.zip").Length / 1MB
Write-Host "Compressed size: $([math]::Round($zipSize, 2)) MB"
```

**Linux/Mac:**
```bash
# Compress vectorstore to tar.gz (better compression)
date=$(date +%Y%m%d_%H%M%S)
tar -czf "vectorstore_backup_${date}.tar.gz" vectorstore/

# Check compressed size
ls -lh vectorstore_backup_${date}.tar.gz
```

**Step 2: Share compressed file**
- **Cloud Storage**: Upload to Google Drive, OneDrive, Dropbox, etc.
- **Network Drive**: Copy to shared network location
- **External Drive**: Copy to USB/external drive
- **File Sharing**: Use services like WeTransfer, SendAnywhere

**Step 3: Extract on recipient machine**

**Windows PowerShell:**
```powershell
# Extract zip file
Expand-Archive -Path vectorstore_backup_20251122.zip -DestinationPath . -Force
```

**Linux/Mac:**
```bash
# Extract tar.gz file
tar -xzf vectorstore_backup_20251122.tar.gz
```

**Compression Notes:**
- **ChromaDB already uses Snappy compression** internally (75-85% reduction)
- **Additional zip/tar.gz compression**: May provide 10-30% further reduction
- **Expected compressed size**: ~1.1-1.4 GB (from 1.52 GB original)
- **Compression time**: 2-5 minutes depending on system
- **Extraction time**: 1-3 minutes

**Sharing Tips:**
- ✅ **Compress before sharing** - Reduces upload/download time
- ✅ **Use date-stamped filenames** - Track versions
- ✅ **Verify integrity** - Check file size after download
- ✅ **Test extraction** - Verify backup works before deleting original

### Q: What's the recommended disk space?

**A**: 
- **Minimum**: 10 GB free space
- **Recommended**: 20+ GB for development
- **Production**: Depends on document volume
